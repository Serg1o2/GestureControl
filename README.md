# GestureControl

Управление телефоном жестами руки через фронтальную камеру. Распознавание идёт полностью на устройстве (MediaPipe Hand Landmarker), без облака и без доступа в интернет.

**Этап 1 (MVP):**

| Жест | Действие |
|---|---|
| Свайп вправо | Следующий трек |
| Свайп влево | Предыдущий трек |
| Открытая ладонь, удержание 0,5 с | Пауза / воспроизведение |

Направление считается с точки зрения пользователя: «вправо» означает, что рука движется к вашей правой руке, как в зеркале.

Жесты работают только в приложениях, выбранных пользователем. Активное приложение определяет служба специальных возможностей, и камера включается только когда оно на экране.

## Требования

- JDK 17, Android SDK (platform 35, build-tools 35.0.0).
- Устройство с Android 8.0+ (minSdk 26) и фронтальной камерой.

На машине разработчика всё установлено в `C:\Users\vladk\dev`: `jdk-17.0.20.1+1`, `android-sdk`, `gradle-8.11.1`. Переменные `JAVA_HOME` и `ANDROID_HOME` прописаны в пользовательском окружении.

## Сборка

```bash
./gradlew assembleDebug              # APK: app/build/outputs/apk/debug/app-debug.apk
./gradlew :gestures:test             # unit-тесты логики жестов (чистый JVM)
./gradlew :app:lintDebug             # Android Lint
./gradlew installDebug               # установить на подключённое устройство
```

При первой сборке Gradle-задача `downloadHandModel` скачивает модель `hand_landmarker.task` (~7,8 МБ) в `app/src/main/assets/`. Модель не хранится в git.

## Первая настройка на устройстве

1. Откройте приложение и разрешите доступ к **камере** и **уведомлениям**.
2. Нажмите «Открыть настройки» и включите службу специальных возможностей **GestureControl**.
   - Если APK установлен не из магазина, на Android 13+ переключатель может быть неактивен («Ограниченная настройка»). Тогда: Настройки → Приложения → GestureControl → ⋮ → **Разрешить ограниченные настройки**, и повторите.
3. «Выбрать приложения»: отметьте, например, Spotify и YouTube Music.
4. Включите главный переключатель «Управление жестами». Появится уведомление с кнопкой «Стоп».
5. Откройте Spotify, запустите трек и проведите рукой перед фронтальной камерой.

Экран отладки показывает превью камеры с 21 точкой руки, состояние машины жестов и fps. Там же можно вручную выполнять действия и записывать последовательности точек для тестов. Пока экран отладки открыт, фоновый сервис отдаёт ему камеру.

## Архитектура

```
:gestures (чистый Kotlin/JVM, без Android)
  Landmark, HandFrame          — модель данных, 21 точка в координатах «как видит пользователь»
  GestureConfig                — все пороги: расстояние, скорость, время, cooldown
  OneEuroFilter                — сглаживание точек
  StaticGestureClassifier      — открытая ладонь
  SwipeDetector                — свайп по траектории центра ладони
  GestureEngine                — машина состояний: удержание, latch, cooldown, подавление обратного свайпа
  PowerSaveThrottler           — 10 fps, когда руки нет в кадре
  LandmarkCsv                  — формат записанных последовательностей

:app
  camera/CameraController      — CameraX ImageAnalysis (+Preview для отладки), фронтальная камера
  vision/HandLandmarkerEngine  — MediaPipe Hand Landmarker, режим VIDEO
  vision/HandAnalyzer          — кадр → поворот + зеркало → точки → GestureEngine
  actions/                     — Action, MediaKeyAction (AudioManager.dispatchMediaKeyEvent), ActionDispatcher
  service/GestureService       — foreground-сервис (type=camera), уведомление со «Стоп», условие включения камеры
  accessibility/               — ForegroundAppService (TYPE_WINDOW_STATE_CHANGED) → ForegroundAppTracker
  data/                        — Room (выбранные приложения), DataStore (настройки), список установленных приложений
  ui/                          — Compose: главный экран, выбор приложений, отладка
```

**Когда работает камера.** Сервис запускается с видимого главного экрана: на Android 14+ камерный foreground-сервис нельзя запустить из фона. Дальше сервис живёт постоянно и включает камеру только при одновременном выполнении условий:
- на экране выбранное приложение;
- экран включён;
- экран отладки закрыт.

## Пороги жестов

Все пороги в `gestures/src/main/kotlin/com/gesturecontrol/gestures/GestureConfig.kt`. Расстояния указаны в долях кадра.

| Параметр | Значение | Смысл |
|---|---|---|
| `swipe.minDistance` | 0.25 | Минимальный горизонтальный путь центра ладони |
| `swipe.minVelocity` | 0.8 /с | Минимальная средняя скорость |
| `swipe.maxDurationMs` | 600 | Окно, в которое должен уложиться свайп |
| `swipe.axisDominance` | 1.5 | Во сколько раз \|dx\| больше \|dy\| |
| `swipe.oppositeSuppressMs` | 900 | Возврат руки не вызывает обратный свайп |
| `palm.holdMs` | 500 | Удержание ладони |
| `palm.maxVelocity` | 0.25 /с | Ладонь должна быть неподвижна |
| `cooldownMs` | 600 | Антидребезг после любого жеста |
| `handLostToleranceMs` | 150 | Пропуск руки на 1–4 кадра не сбрасывает жест |
| `PowerSaveConfig.idleAfterMs` | 1000 | Через сколько без руки включается режим 10 fps |

## Тесты

`./gradlew :gestures:test` запускает 37 тестов: фильтр, классификатор, движок жестов, троттлинг, воспроизведение CSV.

Файлы `gestures/src/test/resources/sequences/*.csv` проигрываются через движок автоматически. Сейчас там лежат **синтетические** последовательности. Чтобы добавить реальную запись:
1. На экране отладки нажмите «Записать точки», сделайте жест, нажмите «Остановить».
2. Заберите файл: `adb pull /sdcard/Android/data/com.gesturecontrol/files/recordings/`.
3. Положите его в `sequences/` и впишите ожидаемые жесты в первую строку: `# expect: SWIPE_RIGHT` (пусто означает «жестов быть не должно»).

## Батарея и нагрев

> **Статус: не измерено.** Замеры требуют реального устройства, которого не было при разработке этапа 1. Ниже методика и таблица для заполнения.

Скрипт `scripts/measure-power.sh` (bash, работает в Git Bash) делает следующее:
- сбрасывает `batterystats`;
- раз в 30 с пишет уровень заряда и температуру батареи;
- в конце сохраняет оценку энергопотребления приложения.

Лучше подключаться по беспроводной ADB, потому что зарядка по USB искажает температуру.

```bash
adb pair <ip:port>  &&  adb connect <ip:port>
scripts/measure-power.sh baseline-spotify 30      # 1) жесты выключены, Spotify играет
scripts/measure-power.sh idle-no-hand 30          # 2) жесты включены, Spotify на экране, руки нет (10 fps)
scripts/measure-power.sh idle-no-powersave 30     # 3) то же, энергосбережение выключено (30 fps)
scripts/measure-power.sh active-hand 10           # 4) рука в кадре постоянно (худший случай)
```

Условия: яркость 50%, Wi-Fi включён, комнатная температура, заряд перед стартом 80–100%, телефон на столе.

| Сценарий | Устройство | Длительность | Расход, п.п. заряда | Δ к базовой линии, п.п./ч | T батареи старт → конец, °C |
|---|---|---|---|---|---|
| 1. Базовая линия (Spotify, жесты выкл.) | — | 30 мин | — | — | — |
| 2. Жесты вкл., руки нет, 10 fps | — | 30 мин | — | — | — |
| 3. Жесты вкл., руки нет, 30 fps | — | 30 мин | — | — | — |
| 4. Рука в кадре постоянно | — | 10 мин | — | — | — |

Ожидания до замеров, это оценка, а не факт:
- камера сама по себе потребляет заметную часть энергии даже при пропуске кадров, потому что энергосбережение сейчас снижает частоту инференса, а не частоту сенсора;
- поэтому разница между сценариями 2 и 3 будет меньше, чем 3×.

## Ручная проверка на устройстве

- [ ] Первый запуск: запрос камеры, уведомлений; включение службы спецвозможностей (в т.ч. обход «Ограниченной настройки»).
- [ ] Экран отладки: точки руки совпадают с рукой на превью, при движении руки вправо точки движутся вправо.
- [ ] Экран отладки: свайпы и ладонь распознаются, «Последний жест» обновляется, fps ~25–30 с рукой и ~10 без руки.
- [ ] Spotify: свайп вправо = следующий трек, влево = предыдущий, ладонь 0,5 с = пауза/воспроизведение.
- [ ] YouTube Music: то же самое.
- [ ] Возврат руки после свайпа не переключает трек обратно; один свайп = одно переключение.
- [ ] Ладонь, удерживаемая 3 с, ставит паузу один раз, а не мигает пауза/плей.
- [ ] Приложение не выбрано (например, браузер): индикатор камеры не горит, жесты не работают.
- [ ] Переход Spotify → домашний экран → Spotify: камера выключается и включается обратно (индикатор, текст уведомления).
- [ ] Шторка уведомлений и клавиатура поверх Spotify не выключают жесты.
- [ ] Выключение экрана: камера выключается; включение и разблокировка в Spotify: включается.
- [ ] Кнопка «Стоп» в уведомлении останавливает сервис, главный переключатель гаснет.
- [ ] Альбомная ориентация (YouTube Music в landscape): направления свайпов правильные.
- [ ] Android 14+: после «Стоп» сервис не перезапускается сам; повторный запуск только из приложения.
- [ ] Разные условия: слабый свет, контровой свет, рука на расстоянии 30 / 60 / 100 см.
- [ ] Замеры батареи и нагрева по таблице выше.

## Известные риски и ограничения

1. **Пороги подобраны на синтетике.** Реальные скорости и амплитуды рук нужно уточнить по записям с экрана отладки. Возможны ложные свайпы при жестикуляции перед камерой.
2. **«Ограниченные настройки» Android 13+** блокируют включение спецвозможностей для APK не из магазина. Нужен ручной обход (см. выше).
3. **Политика Google Play для AccessibilityService.** Использование не для помощи людям с ограничениями требует декларации и может быть отклонено. Для публикации стоит рассмотреть `UsageStatsManager` как альтернативу.
4. **Энергосбережение снижает частоту инференса, но не сенсора.** Камера продолжает выдавать ~30 fps. Дальнейшая экономия возможна через `Camera2Interop` (`CONTROL_AE_TARGET_FPS_RANGE`) с перепривязкой камеры.
5. **Инференс на CPU.** GPU-делегат может быть экономнее, но на части устройств падает. Его стоит проверить отдельно.
6. **Конкуренция за камеру.** Если другое приложение (видеозвонок, камера) возьмёт фронтальную камеру, CameraX отдаст её. Жесты перестанут работать без явного сообщения пользователю.
7. **Агрессивное энергосбережение производителей** (Xiaomi, Huawei, Samsung) может убивать сервис или службу спецвозможностей. Нужно исключить приложение из оптимизации батареи.
8. **Определение активного приложения по событиям окна.** Режимы split-screen, PiP и плавающие окна обрабатываются как «последняя активити».
9. **Медиаклавиши уходят в последнюю активную медиасессию.** Если параллельно играет другой плеер, команда может попасть в него.
10. **Версии зависимостей** зафиксированы (AGP 8.7.3, Kotlin 2.0.21, CameraX 1.4.1, MediaPipe 0.10.20). Lint сообщает о более новых, обновление стоит делать отдельной задачей.
