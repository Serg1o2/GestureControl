# Сведение классов к единому набору

Код: `ml/gc_ml/classes.py`. Порядок классов = индексы выходов модели; новые классы только дописываются в конец, приложение читает порядок из метаданных модели (`assets/models/*.json`).

## Как модели используются в приложении

Распознавание в приложении гибридное:
- **модель позы** (MLP, статичная поза каждого кадра) заменяет геометрические правила классификации позы;
- **машина состояний** (`GestureEngine`, `PointerEngine`) по-прежнему решает, когда сработал жест: свайп по траектории, разжатие кулака по смене поз «кулак → ладонь», удержание ладони по времени, взмах пальцем по позе «указательный» + траектории.

Так модель улучшает самое шумное место (поза), а логика времени и антидребезга остаётся детерминированной и покрытой тестами. Динамическая модель (1D-CNN на окне 24 кадра) обучается и оценивается отдельно (`docs/accuracy.md`) как кандидат на замену правил траектории.

## Статичные позы (модель `pose_mlp`)

| Класс | HaGRIDv2 | MediaPipe Gesture Recognizer (база для сравнения) | Где используется в приложении |
|---|---|---|---|
| `OTHER` | `no_gesture` и все не перечисленные ниже: call, rock, mute, four, three, three2, three3, three_gun, little_finger, middle_finger, holy, hand_heart, hand_heart2, take_picture, timeout, xsign, grabbing, grip, ok, thumb_index, thumb_index2 | None, ILoveYou | «рука есть, жеста нет»: ничего не срабатывает |
| `OPEN_PALM` | palm, stop, stop_inverted | Open_Palm | удержание ладони, конец разжатия кулака, свайп ладонью |
| `FIST` | fist | Closed_Fist | начало разжатия кулака |
| `POINTING` | one, point | Pointing_Up | курсор (в приложениях с зонами), взмах пальцем |
| `TWO_FINGERS` | peace, peace_inverted, two_up, two_up_inverted | Victory | прокрутка двумя пальцами |
| `THUMB_UP` | like | Thumb_Up | пока не назначено (для своих жестов) |
| `THUMB_DOWN` | dislike | Thumb_Down | пока не назначено |

**«Нет жеста» обязателен и широк:** в `OTHER` попадают и руки без жеста (`no_gesture` HaGRID — руки в естественном положении рядом с лицом/телом), и 21 «чужая» поза. Это и есть фон для оценки ложных срабатываний.

**Щипок** (`PINCH`) в набор модели не входит: в открытых датасетах нет позы «большой и указательный сомкнуты, остальные согнуты» (`ok` HaGRID — три пальца вытянуты). Щипок определяется геометрией (расстояние кончиков / размер руки), как в этапе 2.

## Динамические жесты (модель `dynamic_cnn`)

| Класс | IPN Hand | Направление |
|---|---|---|
| `NO_GESTURE` | D0X (не-жест), B0A/B0B (указание одним/двумя пальцами — движения курсора не должны срабатывать), G01/G02 (клик), G08/G09 (двойной клик), G10/G11 (zoom) | — |
| `SWIPE_LEFT` | G05 throw left | влево **от пользователя** |
| `SWIPE_RIGHT` | G06 throw right | вправо от пользователя |
| `SWIPE_UP` | G03 throw up | вверх |
| `SWIPE_DOWN` | G04 throw down | вниз |
| `FIST_OPEN` | G07 open twice (кулак раскрывается дважды) | — |

**Взмах пальцем влево/вправо** (`FINGER_LEFT/RIGHT`) в открытых датасетах отсутствует: у Jester есть только «два пальца», у IPN — «бросок» всей рукой. Поэтому он распознаётся правилами (поза `POINTING` от модели + траектория кончика пальца), а данные для него появятся из логгера обучения.

### Зеркальность

Приложение работает в координатах «как видит пользователь» (кадр фронтальной камеры зеркалится, x растёт вправо от пользователя). Видео IPN записаны веб-камерой; при извлечении точек x отражается (`MIRROR_TO_USER_VIEW` в `gc_ml/ipn.py`), чтобы «throw left» означал движение влево от пользователя. Проверка на данных — в `docs/accuracy.md` (средний сдвиг ладони в окнах G05/G06 после отражения должен быть отрицательным/положительным).

Для статичной позы зеркальность не важна: нормализация приводит левую и правую руку (и зеркальную камеру) к одной хиральности.
