# План: громкость щипком («ползунок»)

_Подготовлено 22.10.2026, реализация не начата. Вариант 2 из обсуждения: свести большой и указательный пальцы и двигать руку вверх / вниз — громкость меняется вслед за движением; развести пальцы — закончить._

## Поведение для пользователя

1. Свести большой и указательный (остальные пальцы согнуты) и задержать ~0,2 с — ползунок «взведён» (лёгкая вибрация).
2. Двигать руку вверх — громче, вниз — тише. Один шаг громкости на каждые ~0,25 размера ладони (настраивается чувствительностью). Движение назад в том же щипке возвращает громкость.
3. Развести пальцы — ползунок отпущен. После этого ~0,8 с не срабатывают другие жесты (раскрытая ладонь не ставит паузу).
4. Работает только в выбранных приложениях **без зон** (в приложениях с зонами щипок — это нажатие) и, по умолчанию, только когда играет музыка.
5. Обратная связь: системная панель громкости Android, вибрация на шаг (если есть разрешение VIBRATE).

## Что есть в коде сейчас (важно для реализации)

- `ActionExecutor` уже меняет громкость для своих жестов: `audio.adjustStreamVolume(STREAM_MUSIC, ADJUST_RAISE/LOWER, FLAG_SHOW_UI)` — новых разрешений не нужно.
- `PointerEngine` в приложениях без зон выключен (`active = cursorApp`), поэтому ползунок живёт в **`GestureEngine`**, а не в курсоре.
- Геометрия щипка сейчас приватная в `PointerEngine`: `othersFolded()`, `indexReach() >= pinchMinIndexReach`, `StaticGestureClassifier.pinchRatio()`, гистерезис `pinchClose 0.30 / pinchOpen 0.45`. Её нужно **вынести в общий `PinchTracker`** (`:gestures`), а не копировать.
- Щипок модель поз часто видит как POINTING → в приложениях без зон это ветка взмаха пальцем (`fingerSwipesEnabled`). Пока ползунок активен, взмахи пальцем и свайпы должны сбрасываться.
- Раскрытие руки после щипка = OPEN_PALM → удержание ладони может сработать паузой. Нужна блокировка после отпускания.
- Режимы переключаются в `GestureService.applyModeFlags()` (`fingerSwipesEnabled = !cursorApp`) — туда же флаг ползунка.
- Свои жесты (`CustomGestureRecognizer`) получают те же кадры — проверить, что движение щипком не срабатывает как свой жест (или не подавать кадры, пока ползунок активен).

## Архитектура

**`:gestures` (чистый Kotlin, тесты):**
- `PinchTracker` — общий для `PointerEngine` и ползунка: закрыт/открыт с гистерезисом, `minClosedFrames`, допуск выпадения кадров. `PointerEngine` переводится на него без изменения поведения (существующие тесты должны пройти как есть).
- `VolumeSliderConfig` в `GestureConfig`: `armMs = 200`, `armMaxMotion` (рука почти неподвижна во время взвода, в размерах руки), `stepHandSizes = 0.25`, `deadZoneHandSizes = 0.15`, `maxStepsPerPinch = 10`, `releaseToleranceMs = 120`, `afterReleaseSuppressMs = 800`.
- `VolumeSlider` (детектор): Idle → Arming → Active(startY, emittedSteps) → Idle. В Active смещение центра ладони по вертикали в размерах руки (изотропно, как свайп) переводится в целое число шагов от точки взвода; при изменении на ±1 — событие. Сброс при потере руки, скачке трекинга (`TrackingGuard`), раскрытии.
- Новые `Gesture.VOLUME_UP` / `VOLUME_DOWN` — по событию на шаг. Они **не** запускают общий cooldown (иначе шаги будут через 0,6 с), но пока ползунок активен, остальные жесты подавлены; после отпускания — `afterReleaseSuppressMs`.
- `GestureEngine.volumeSliderEnabled` (как `fingerSwipesEnabled`) + `EngineState.VolumeSliding(steps)` для экрана отладки.
- `GestureToggles.volume` (по умолчанию включён), `Sensitivity.volume` (шаг в размерах руки × factor, время взвода × factor).

**`:app`:**
- `ActionDispatcher`: VOLUME_UP/DOWN → `adjustStreamVolume(STREAM_MUSIC, …, FLAG_SHOW_UI)`; если включено «только когда играет музыка» и `!audioManager.isMusicActive` — игнорировать (решение на старте щипка, а не на каждый шаг).
- `GestureService.applyModeFlags()`: `volumeSliderEnabled = !cursorApp`; кастомные жесты не получают кадры, пока ползунок активен.
- `SettingsRepository`: `volumeOnlyWhenPlaying` (по умолчанию true), переключатель и чувствительность — через существующие `GestureToggles` / `Sensitivity`.
- UI: плитка «🤏↕ Щипок вверх / вниз → громкость» в списке жестов; карточка в «Настройке жестов» (переключатель, ползунок чувствительности, «только когда играет музыка»); экран отладки показывает «ползунок: +3». Строки RU и EN.
- Вибрация на шаг — только если разрешение VIBRATE уже есть в манифесте; иначе обойтись панелью громкости (добавление разрешения — отдельно согласовать).

## Порядок работы (каждый шаг: тесты + сборка зелёные, затем коммит)

1. **Стенд, «до»:** базовая линия фантомов на IPN (`./gradlew :gestures:replayBench -PbenchArgs="--split test --config default"`), добавить в стенд подсчёт VOLUME-событий по видам активности. Особое внимание `zoom` (G10/G11 — щипки масштаба) и `click`: это главные источники ложных срабатываний ползунка.
2. **`PinchTracker`:** вынести из `PointerEngine`, все тесты курсора без изменений.
3. **`VolumeSlider` + тесты:** синтетика (`SyntheticHand.Pose.PINCH` + движение): взвод, шаги вверх/вниз, возврат, мёртвая зона, лимит шагов, отпускание, потеря руки, скачок трекинга, низкий fps (15 и 10), «щипок без движения» = 0 шагов, «быстрый щипок-разжатие» = 0 шагов, раскрытие после ползунка не даёт OPEN_PALM_HOLD, POINTING-взмах подавлен во время ползунка.
4. **Интеграция в `GestureEngine`**, флаги, toggles/sensitivity (+ тесты `GestureTogglesTest`, `SensitivityTest`).
5. **Стенд, «после»:** фантомы VOLUME в покое ≤ 0,1/мин, на щипках масштаба — записать как есть; общие фантомы и попадания других жестов не хуже, чем были. Если хуже — подбирать `armMs` / `armMaxMotion` / `deadZone` на train+val, проверять на test.
6. **Приложение:** действие, флаги в сервисе, настройки, UI, экран отладки, строки, скриншоты Paparazzi (пересъёмка и просмотр).
7. **Документация:** README (таблица жестов), `docs/phantoms.md` (цифры), CLAUDE.md (правило про ползунок), версия 0.7.0, APK на телефон.

## Риски

- Ложные срабатывания на щипках масштаба и «кликах» — главная метрика, решается взводом с неподвижностью и мёртвой зоной.
- Темнота: расстояние большой–указательный шумное → гистерезис + допуск выпадений; проверить на затемнённых потоках стенда (`dark_none`, `dark2x_none` @15 fps).
- Удержание громкости «на краю кадра»: рука уходит из кадра вверх — ползунок отпускается по потере руки, громкость остаётся последней.
- Разные приложения музыки: громкость STREAM_MUSIC общая, приложение-источник не важно.
